# 串口协议

## 串口配置

- Zigbee：两车 UART0，9600、8N1。
- K230：两车 UART1，38400、8N1。
- 调试/参数：两车 UART2，115200、8N1。

## Zigbee 双车帧

```text
18 D1 D2 19
```

2车解析的命令如下：

| 负载 | 含义 |
|---|---|
| `10 10` | 启动 Q1 |
| `1A 1A` | Q1 停止事件 |
| `20 20` | 启动 Q2 |
| `2A 2A` | Q2 停止事件 |
| `30 30` | 启动 Q3 |
| `3A 3A` | Q3 停止事件 |
| `40 40` | 启动 Q4 |
| `4A 4A` | Q4 辅助停车标志置位 |
| `4B 4B` | Q4 辅助停车标志清零 |
| `4C 4C` | Q4 最终停车事件 |

2车 Q6 停车分支会发送 `18 A6 A6 19`，1车解析器可把它映射为 `Q6_Stop_Flag=1`，但1车当前没有启用 Zigbee 接收中断或调用解析函数，因此这条链路在现状下不生效。

协议没有校验和、序号、ACK、重发或超时机制。无线丢帧、重复帧、乱序和任一车辆复位都必须单独验证。

## K230 → 1车

```text
AA L_H L_L M_H M_L FLAGS 55
```

当前解析器只使用 `FLAGS`：bit7 → `Fork_Flag`，bit0 → `Stop_Flag`；四个坐标字节的赋值已被注释。1车主循环当前也没有调用该解析器。

## K230 → 2车 Q6 事件

```text
21 D1 D2 22
```

- `F1 F1`：设置准备超车标志。
- `F2 F2`：进入超车动作。
- `F3 F3`：进入停车分支。

用户提供的项目目录没有对应 K230 程序，因此这里只能证明 MCU 侧格式，不能证明端到端协议匹配。
